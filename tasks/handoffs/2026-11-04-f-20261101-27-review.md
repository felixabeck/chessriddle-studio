# Plan: folder Move must not move or create a PGN metadata sidecar

## Goal

Moving a folder in the Files workspace moves only the folder. A sibling PGN's `.info` sidecar with
the same stem stays where it is, and no `<folder>.info` object is created at the destination.

## MANDATE

f-20261101-27 (verbatim fields):

* **Where:** `src-tauri/src/infra/path_authority/mod.rs:5065-5070` (`workspace_sidecar_leaf` uses `file_stem`: folder `Sicilian` and `Sicilian.pgn` both map to `Sicilian.info`), `src-tauri/src/file_workspace.rs:2030-2045` (move has no `is_dir` branch), `:1486-1503` (`paired_rename_inner` moves the regular file of that name), `:1525-1530` (a folder move without sibling creates `<folder>.info` at the target), `:1699-1701` (create refuses a name whose sidecar exists). Trash and restore already skip the sidecar for folders.
* **Defect:** moving a folder moves or creates a sidecar that belongs to a PGN.
* **Failure scenario:** root holds folder `Sicilian/` and `Sicilian.pgn` typed Repertoire with tags; moving the folder into `Archive/` moves `Sicilian.info` along, so `Sicilian.pgn` loses its type and tags and later `Archive/Sicilian.pgn` is refused as "name already used".
* **Open question:** `d-20261022-25` rejected "skip every directory's sidecar boundary"; how should move treat a directory's sidecar so it never claims a sibling file's sidecar, consistent with trash/restore and that decision?

## Threat model and non-goals

Input: the user's own workspace directory, mutated by the app and possibly by external tools
(a file manager, sync client, git) between and during app operations. External tools may leave
arbitrary names in it, including a directory named `games.info`, a regular `X.info` beside a folder
`X`, or case variants on case-insensitive filesystems. The renderer reaches entries only through
registered `FileWorkspaceHandle`s, and that authority is unchanged. Environments: Linux, macOS,
Windows (case-sensitive and case-insensitive volumes). No adversary beyond concurrent external
mutation, which the existing descriptor-relative identity checks already cover.

Non-goals: repairing workspaces already affected by earlier folder moves (a stray default
`<folder>.info`, or a PGN sidecar that already travelled with a folder). Ownership of such a file
cannot be attributed after the fact. File (PGN) move, rename, trash and restore sidecar behavior
stays unchanged.

## Traced premises

* `src-tauri/src/infra/path_authority/mod.rs:5065-5069`: `workspace_sidecar_leaf` derives
  `<file_stem>.info`, so a folder `Sicilian` and the file `Sicilian.pgn` share `Sicilian.info`.
* `src-tauri/src/file_workspace.rs:2012-2068` (`move_workspace_entry_blocking`): calls
  `paired_workspace_rename` for files and directories alike, with default metadata bytes.
* `file_workspace.rs:1441-1595` (`paired_rename_inner`): after the primary rename it observes
  `<source stem>.info` in the source parent, renames it to the target if present (`Moved`). Otherwise,
  on the forward path, it creates `<target stem>.info` with default metadata (`Created`). For
  directories only, it first checks whether that name is the moved directory itself (`PrimaryAlias`,
  d-20261022-25).
* `file_workspace.rs:2245-2258` (trash) and `:2339-2352` (restore): a directory source does only
  `rename_entry_at(..., true, ...)` with disposition `Absent`. Files use `paired_rename_inner(..., None)`.
* `file_workspace.rs:2471-2477` (permanent delete): directories skip sidecar cleanup.
* `file_workspace.rs:905-971` (listing): directory entries carry `metadata: None`. Only files
  read a sidecar.
* `file_workspace.rs:2120` (`rename_workspace_file_blocking`) and `:465`
  (`write_workspace_file_metadata_blocking`): both refuse directories. No command writes directory
  metadata.
* `file_workspace.rs:152-160` (`validate_name`): new names ending in `.info` are refused. Externally
  created ones are still listed and movable.
* `src-tauri/src/infra/fs.rs:6011-6048`: `rename_entry_at` and `rename_workspace_entry_at` share
  `rename_entry_at_with_collision`. The workspace variant gives the typed forward collision
  classification (conflict/nameTaken) that d-20261022-18..25 established for Move.
* Tests that encode the current directory pairing: `folder_sidecar_alias_*`
  (`file_workspace.rs:6243-6540`, among them a refusal when a foreign `X.info` sits at the
  destination of folder `X`, and creation of a default `games.info` beside a moved `games.INFO`
  folder on case-sensitive volumes).

## Approach

### O1 — Directories have no workspace sidecar in any paired move

A directory never owns a `.info` sidecar. No command writes one, listing never reads one, and
trash, restore and delete already ignore it. The shared pair primitive (`paired_rename_inner`, used
by Move, file Rename, Trash and Restore) therefore performs only the primary rename for a directory
source and returns disposition `Absent`. For directories it does not observe, rename, create or
alias-check any `.info` name in either parent. Move keeps the forward collision variant for the
directory primary, so an existing entry with the folder's own name still gives the typed
conflict/nameTaken refusal. Trash and restore keep the non-forward variant. The duplicated
directory branches in trash and restore are routed through this one primitive, so the rule lives in
one place (async-resource-invariants: the second similar implementation is extracted). Files
keep their current paired behavior byte for byte. Compensation for a directory Move after a
committed primary (cancellation, rebind failure) reverses only the primary, through the existing
`compensate_workspace_rename` with `Absent`.

### O2 — Retire the directory alias mechanism and supersede d-20261022-25

`PrimaryAlias`, its pre-alias observation hook and the alias branch can only be reached for
directories, so O1 makes them dead and they are removed. d-20261022-25 is superseded by the new
decision below. Its protected invariants still hold: a listed `games.info` (or `games.INFO`)
directory moves successfully with its own and its children's handles rebound. Foreign destination
bytes are untouched (now trivially, since nothing is created). Cancellation and committed-outcome
handling are unchanged. The alias tests become regressions of the new contract rather than being
deleted without replacement.

### O3 — Verification

Real-producer regressions in `file_workspace.rs` tests, driven through the Move, Trash, Restore and
Create blocking entry points over a real listed workspace:

1. MANDATE scenario: root holds `Sicilian/` (with a child PGN) and `Sicilian.pgn` plus a
   non-default `Sicilian.info`. Moving the folder into `Archive/` succeeds, `Sicilian.info` stays
   at the root byte-identical, and the listing shows `Sicilian.pgn` with its metadata. `Archive/`
   contains only `Sicilian`, and creating `Archive/Sicilian.pgn` afterwards succeeds.
