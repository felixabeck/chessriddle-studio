### Decided autonomously

* **Question:** How does the analysis layout give the notation card a usable minimum height at
  large font scales without changing the 100% desktop composition (f-20261101-32)?
* **Governs:** f-20261101-32
* **Chosen:** a rem-based minimum height on the notation scroll viewport for `topBar` hosts, with
  the card no longer collapsing below header + floor, and the `#bottomRight` column of the two
  `topBar` hosts (`BoardAnalysis`, `BoardGame`) scrolling vertically through one shared column
  component when its content does not fit. Header, Mosaic defaults and the `Puzzles`/`GamePreview`
  hosts are unchanged.
* **Rejected:** header icons forced onto one compact row with name truncation (changes the 100%
  composition for long opening names and still overflows horizontally at 800px/200%); a different
  card split or Mosaic default (changes the 100% composition, does not cover resized splits).
* **Reason:** the floor with outer scrolling holds for every font scale and window size with a
  non-collapsed tile and is a no-op wherever the content already fits, which is the 100% default
  composition. Proven by the `font-scaled-breakpoints` e2e cells at 1000x720 and 800x720 (seen red
  pre-fix and with the column scrolling reverted) and all committed snapshots unchanged. Reversal
  path: revert the phase commit; `notation-hierarchy-scaled` then returns to 1000x1100 per
  d-20261102-02.
* **Decided by:** Claude Code (orchestrator), drain plan-only run, full auto, plan review r1-r3.

# Plan: Notation keeps visible move rows at 200% font scale in small windows (f-20261101-32)

## Goal

At any app font scale and window size, the analysis (and play) notation card shows move rows.
At 200% font scale in a 1000x720 or 800x720 window the notation scroll viewport mounts and
shows moves instead of collapsing to zero height under the wrapped header. The default 100%
desktop composition is unchanged.

## MANDATE

From `tasks/findings.md`, f-20261101-32 (verbatim):

* **Defect:** At 200% app font size, in a 1000x720 and an 800x720 window, the notation card's header icons (hide moves, table view, comments, variations) wrap onto two lines and take the card's whole height. The notation scroll viewport gets about zero height, so the virtualizer mounts no move rows. Observed in the pinned Playwright container (master styling and the notation-hierarchy build alike), screenshot inspected.
* **Failure scenario:** A user sets the app font size to 200% and opens a game in a 1000x720 window. The notation panel shows only header icons and no moves. Moves are reachable only by keyboard or the move buttons, without seeing the notation.
* **Open question:** How should the analysis layout give the notation card a usable minimum height at large font scales (header icons on one compact row, a minimum notation height with outer scrolling, or a different card split), without changing the 100% desktop composition?
* Verification hook (annotation on the finding): "When this is fixed, move that project to the 320x720 / 200% matrix cell so the variation-block indent and guide lines are also checked for horizontal overflow at the narrowest width (review-tests diff round 1 finding #1, deferred here)."

Governing decision d-20261102-02: the `notation-hierarchy-scaled` e2e project uses 1000x1100
only because of this defect; "Reversal path: when f-20261101-32 is fixed, move the project to
320x720 as annotated on that finding."

## Threat model and non-goals

No adversary: this is layout. Environments: the renderer in the Tauri webview and the pinned
Playwright container (Chromium), app font scale 50–200% (`fontSizeAtom`, applied as the root
`font-size` percentage in `src/App.tsx`), any window size, and any user-dragged Mosaic split
(`minimumPaneSizePercentage: 0`). Non-goals: changing notation row styling, the header's
controls or labels, the Mosaic default split, or the 100% composition at the default layout.

## Traced premises

* `src/components/common/GameNotation.tsx:211-283` — the card is `Paper flex={1}`
  (`overflow: hidden`) → `Group h="100%"` → toolbar column + `Stack h="100%"` holding
  `NotationHeader` (when `topBar`) and the notation `ScrollArea flex={1}`. Nothing gives the
  ScrollArea a minimum height, so it absorbs all shrinkage.
* `src/components/common/GameNotation.tsx:290-336` — `NotationHeader` is `Stack pt="xs"` →
  `Group justify="space-between"` (Mantine default `wrap="wrap"`) holding `OpeningName`

  rem-based) → `Divider`. All sizes are rem, so they double at 200%, and the name and icons
  wrap onto separate lines when the name is long or the card is narrow.

  `Stack h="100%" gap="xs"` with `DetachedEval`, `GameNotation topBar controls=…` and
  `MoveControls`. `src/components/boards/BoardGame.tsx:1496-1523` has the identical shape
  (without `DetachedEval`). Neither Stack scrolls.
* `src/components/common/MoveControls.tsx` — `Group grow` of four `size="lg"` icons (rem).
* `src/state/layoutStorage.ts:61-74` — default Mosaic: row split left | (topRight / bottomRight),
  so `#bottomRight` is about half the window width and under half its height.
* `src/components/tabs/BoardsPage.tsx:487-494` — `resize={{ minimumPaneSizePercentage: 0 }}`:
  the user can also drag the card arbitrarily small at 100%.
* `src/components/puzzles/Puzzles.tsx:1226-1248` renders `GameNotation` without `topBar` in its
  own column; `src/components/databases/GamePreview.tsx:142-172` renders it without `topBar`

  the wrapped header ≈ 200px; the notation viewport ≈ 0.

## Approach

### O1 — Notation floor (MANDATE: "give the notation card a usable minimum height at large font scales")

When `GameNotation` renders with `topBar`, the notation scroll viewport has a minimum height
expressed in `rem` (so it scales with the app font size), defined once as a named constant in
`GameNotation.tsx` and sized to show at least three inline move rows. The card (`Paper`) must not
shrink below header + floor: its minimum height follows its content instead of collapsing to 0
under `overflow: hidden`. Hosts without `topBar` (`Puzzles`, `GamePreview`) are unaffected —
`GamePreview` owns a computed notation height that a floor would break.

### O2 — Card column scrolls instead of compressing (MANDATE option "a minimum notation height with outer scrolling")

When header + floor + sibling cards (`DetachedEval`, `MoveControls`) exceed the `#bottomRight`
tile, the tile's column scrolls vertically; no child is clipped and no child compresses below
its own content. This is one concept shared by the two `topBar` hosts (`BoardAnalysis`,
`BoardGame`), so it is extracted once (one shared column component or class next to
`GameNotation`) and both hosts route through it. When everything fits, the column does not
scroll and nothing moves: the 100% default composition is pixel-identical.

### O3 — Verification (MANDATE verification hook and d-20261102-02 reversal path)

* A test in `e2e/font-scaled-breakpoints.spec.ts` (project `font-scaled-breakpoints`, already
  1000x720 at font scale 200 — this finding's reproduction cell) opens a game on the analysis
  board in 1000x720 and, via `page.setViewportSize`, 800x720 and asserts: the notation viewport has mounted move rows, its `clientHeight` is at least the floor,
  and the current main-line move is visible after `scrollIntoViewIfNeeded` (outer scroll path).
  It was seen red on the pre-fix tree (viewport count with the main SAN = 0).
* The 100% composition is proven unchanged by every existing committed e2e snapshot passing
  without re-recording (the full container suite, which includes every project whose screenshot
  contains `#bottomRight`).
* Per d-20261102-02's reversal path, `notation-hierarchy-scaled` moves from 1000x1100 to 320x720
  and its f-20261101-32 comment is removed. If the overflow-only test then fails for a reason
  other than this finding (a horizontal-width defect of the 320px column), the project instead
  moves to 1000x720 (this finding's reproduction cell), the 320px defect is filed as a new
  finding, and a decision superseding d-20261102-02's reversal path is recorded.

## Decisions and trade-offs

* Chosen: O1 + O2 (floor with outer scrolling). Holds for every font scale, every window size and
  every user-dragged Mosaic split, and changes nothing when space suffices.
* Rejected: header icons forced onto one compact row (`wrap="nowrap"` with name truncation) —
  changes the 100% composition for long opening names (today the icons wrap under a long name at
  100% too) and still overflows horizontally at 800px/200% (four ~56px icons + gaps ≈ 296px
  wider than the ≈ 250px card). Rejected: a different card split (changing the Mosaic default) —
  changes the 100% composition and does not cover user-dragged splits.

## Risks / open questions

* At 200% in a 1000x720 window the column scrolls, so `MoveControls` may start below the fold.
  Accepted: the notation is readable and the controls are one scroll away; keyboard navigation
  is unchanged.
* The scroll-to-current reveal in `GameNotation` reads the notation viewport geometry; with a
  floor the viewport is never 0px tall, which only helps it.

* `Puzzles` notation column (no header; no observed failure).

# Plan: Notation keeps visible move rows at 200% font scale in small windows (f-20261101-32)

## Goal

At any app font scale and window size, the analysis (and play) notation card shows move rows.
At 200% font scale in a 1000x720 or 800x720 window the notation scroll viewport mounts and
shows moves instead of collapsing to zero height under the wrapped header. The default 100%
desktop composition is unchanged.

## MANDATE

From `tasks/findings.md`, f-20261101-32 (verbatim):

* **Defect:** At 200% app font size, in a 1000x720 and an 800x720 window, the notation card's header icons (hide moves, table view, comments, variations) wrap onto two lines and take the card's whole height. The notation scroll viewport gets about zero height, so the virtualizer mounts no move rows. Observed in the pinned Playwright container (master styling and the notation-hierarchy build alike), screenshot inspected.
* **Failure scenario:** A user sets the app font size to 200% and opens a game in a 1000x720 window. The notation panel shows only header icons and no moves. Moves are reachable only by keyboard or the move buttons, without seeing the notation.
* **Open question:** How should the analysis layout give the notation card a usable minimum height at large font scales (header icons on one compact row, a minimum notation height with outer scrolling, or a different card split), without changing the 100% desktop composition?
* Verification hook (annotation on the finding): "When this is fixed, move that project to the 320x720 / 200% matrix cell so the variation-block indent and guide lines are also checked for horizontal overflow at the narrowest width (review-tests diff round 1 finding #1, deferred here)."

Governing decision d-20261102-02: the `notation-hierarchy-scaled` e2e project uses 1000x1100
only because of this defect; "Reversal path: when f-20261101-32 is fixed, move the project to
320x720 as annotated on that finding."

## Threat model and non-goals

No adversary: this is layout. Environments: the renderer in the Tauri webview and the pinned
Playwright container (Chromium), app font scale 50–200% (`fontSizeAtom`, applied as the root
`font-size` percentage in `src/App.tsx`), any window size, and any Mosaic split that leaves the
`#bottomRight` tile non-collapsed. A tile the user drags to (near) zero size is clipped by
`.mosaic` (`overflow: hidden`, `src/styles/react-mosaic.css`) and is out of scope: no floor
inside a collapsed pane can make moves visible, and split management is not this task. Non-goals: changing notation row styling, the header's
controls or labels, the Mosaic default split, or the 100% composition at the default layout.

## Approach

### O1 — Notation floor (MANDATE: "give the notation card a usable minimum height at large font scales")

When `GameNotation` renders with `topBar`, the notation scroll viewport has a minimum height
expressed in `rem` (so it scales with the app font size), defined once as a named constant in
`GameNotation.tsx` and sized to show at least three inline move rows. The card (`Paper`) must not
shrink below header + floor: its minimum height follows its content instead of collapsing to 0
under `overflow: hidden`. Hosts without `topBar` (`Puzzles`, `GamePreview`) are unaffected —
`GamePreview` owns a computed notation height that a floor would break.

### O2 — Card column scrolls instead of compressing (MANDATE option "a minimum notation height with outer scrolling")

When header + floor + sibling cards (`DetachedEval`, `MoveControls`) exceed the `#bottomRight`
tile, the tile's column scrolls vertically; no child is clipped and no child compresses below
its own content. This is one concept shared by the two `topBar` hosts (`BoardAnalysis`,
`BoardGame`), so it is extracted once (one shared column component or class next to
`GameNotation`) and both hosts route through it. When everything fits, the column does not
scroll and nothing moves: the 100% default composition is pixel-identical.

### O3 — Verification (MANDATE verification hook and d-20261102-02 reversal path)

* A test in `e2e/font-scaled-breakpoints.spec.ts` (project `font-scaled-breakpoints`, already
  1000x720 at font scale 200 — this finding's reproduction cell) opens a game on the analysis
  board in 1000x720 and, via `page.setViewportSize`, 800x720 and asserts:
  * the notation viewport has mounted move rows and its `clientHeight` is at least the floor;
  * the notation viewport's bounding rect lies inside its card's (`Paper`, `overflow: hidden`)
    bounding rect, so the floor is not merely extending past a clipping card (O1's "the card must
    not shrink below header + floor");
  * after user wheel scrolling of the column, a main-line SAN button in the notation is
    hit-testable (`document.elementFromPoint` at its centre returns it or a descendant);
  * the `#bottomRight` column actually overflows (`scrollHeight > clientHeight`) in this cell, so
    the outer-scroll path is exercised rather than vacuously passing;
  * after **user** scrolling of the column (`page.mouse.wheel` over the column, never
    `scrollIntoViewIfNeeded`, which can scroll an `overflow: hidden` ancestor programmatically),
    the last `MoveControls` button ("Go to end") is hit-testable: `document.elementFromPoint` at
    its centre returns that button (or a descendant), which fails if any ancestor clips it.
  The same column assertions (overflow, wheel scroll, hit-tested "Go to end", notation viewport
  at least the floor and inside its card; the setup state has no moves, so no SAN hit-test) run
  for the play host: a new tab's "Play" opens `BoardGame` in its setup
  state, whose `#bottomRight` renders the same notation column (`BoardGame.tsx:1496-1523`).
  The analysis assertions were seen red on the pre-fix tree (no mounted rows); the wheel/hit-test
  assertion is also seen red with the floor kept but the column's scrolling reverted.
* The 100% composition is proven unchanged by every existing committed e2e snapshot passing
  without re-recording (the full container suite, which includes every project whose screenshot
  contains `#bottomRight`).
* Per d-20261102-02's reversal path, `notation-hierarchy-scaled` moves from 1000x1100 to 320x720
  and its f-20261101-32 comment is removed. If the overflow-only test then fails for a reason
  other than this finding (a horizontal-width defect of the 320px column), the project instead
  moves to 1000x720 (this finding's reproduction cell), the 320px defect is filed as a new
  finding, and a decision superseding d-20261102-02's reversal path is recorded.

## Decisions and trade-offs

* Chosen: O1 + O2 (floor with outer scrolling). Holds for every font scale and window size with a
  non-collapsed `#bottomRight` tile, and changes nothing when space suffices.
* Rejected: header icons forced onto one compact row (`wrap="nowrap"` with name truncation) —
  changes the 100% composition for long opening names (today the icons wrap under a long name at
  100% too) and still overflows horizontally at 800px/200% (four ~56px icons + gaps ≈ 296px
  wider than the ≈ 250px card). Rejected: a different card split (changing the Mosaic default) —
  changes the 100% composition and does not cover user-resized splits.

  Accepted: the notation is readable and the controls are one scroll away; keyboard navigation
  is unchanged.
* The scroll-to-current reveal in `GameNotation` reads the notation viewport geometry; with a
  floor the viewport is never 0px tall, which only helps it.
