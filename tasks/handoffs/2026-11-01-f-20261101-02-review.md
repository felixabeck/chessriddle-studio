* **Question:** how does f-20261101-02 remove the paired revocation-test failure?
  **Chosen:** reserve the refused-connection test's port with a bound, non-listening, non-reuseaddr
  socket for the whole dial, and assert the reservation. **Rejected:** (1) paused tokio time or a
  wider 3 s join bound — the measured cause is a foreign connection, not latency, so both hide the
  race (and a longer join only delays the same red); (2) dialling a fixed "never-listening" port
  such as `127.0.0.1:1` — any process on the host may listen there, and port 0 dials are
  platform-defined; (3) a non-routable address (TEST-NET) — turns a refused-connection test into a
  2 s timeout test and changes what it proves; (4) hardening `loopback_revocation` to reject foreign
  requests — treats the symptom in the victim, and the redacts test would still observe a foreign
  server's answer. **Reason:** measured reuse 5/20000 and zero reuse while held; one-test change;
  deterministic regression assertion. **Reversal path:** if a platform runner refuses
  bind-without-listen or reports a different error kind for the rebind assertion, gate the
  assertion per platform with the measured kind rather than dropping the reservation.

### lens-correctness-r1.txt

The plan’s O1–O3 contracts match the surrounding revocation code, the loopback fixture, and the measured bind-table behaviour. One collision (redacts dials a port `loopback_revocation` was just handed) produces both observed failures.

**Traced path.** `production_revocation_redacts_connection_failure` (`oauth.rs:1746-1761`) binds `std::net::TcpListener` on `127.0.0.1:0`, drops it, then dials that port. `loopback_revocation` (`oauth.rs:1434-1463`) binds `tokio::net::TcpListener` on `127.0.0.1:0` (Unix `SO_REUSEADDR`), accepts exactly `responses.len()` times (one for the bearer test), and joins under a 3 s wall timeout. `revoke_token_before` (`oauth.rs:360-434`) maps 2xx → `Revoked`, 429 → `RateLimited`, other non-401 → `Rejected`, and every send/chunk error plus `timeout_at` → `Unreachable`. A stall therefore cannot fail the redacts `assert_eq!(…, Unreachable)`; a foreign HTTP answer can. If that answer consumes the fixture’s only accept, the bearer client sits on `REVOCATION_TIMEOUT` (30 s) and the 3 s join expires. O3 leaving that join and production mapping unchanged is consistent with that cause.

**O1 reservation.** `tokio::net::TcpSocket::new` does not set `SO_REUSEADDR` (`tokio-1.50` `socket.rs`); `TcpListener::bind` does, on Unix. A bound, non-listening, non-reuseaddr holder is the combination `reuseaddr.py` measured as blocking both `bind(0)` and an explicit reuseaddr `bind`+`listen` (`EADDRINUSE`). A holder *with* `SO_REUSEADDR` is the combination that allows a second listen — so both “never listen” and “do not set reuseaddr” are required. Dial of that holder is `ECONNREFUSED` on Linux (`bound.py`); Windows refused-after-retry/timeout still maps to `Unreachable` via `oauth.rs:368` / `434`. The 2 s reqwest timeout and `assert_token_free_outcome` stay aligned with the current test.

**O2.** Asserting `std::net::TcpListener::bind(same addr)` → `ErrorKind::AddrInUse` while the holder is live is the explicit-rebind case already measured against a reuseaddr competitor. With the pre-fix `drop(listener)` that bind succeeds, so the guard is deterministic and does not need the original race. `d-20261026-06` governs the deadline fixture (`oauth.rs:1608-1743`); this plan does not touch it.

**Limitations (not findings).** macOS/Windows `ErrorKind` and Windows SYN-retry timing were not re-measured here; the plan already routes those through `rust-macos-test` / `rust-windows-test` and a per-platform kind gate rather than dropping the reservation. The original failing `left:` value was not captured; the non-`Unreachable` set is still the only set that can fail `oauth.rs:1760`.

### lens-platform-semantics-r1.txt

The class applies: O1/O2 are a loopback bind, `SO_REUSEADDR`, and refused-connect contract that differs on Linux, macOS, and Windows.

## Approach

### Answer to the open question

Root cause: ephemeral-port reuse. The redacts test frees port P and dials it after a delay; under
a parallel suite a `loopback_revocation` fixture can be handed P. Its single scripted response
(for the bearer test, e.g. `200 OK`) answers the redacts test's DELETE, so the redacts test
observes a non-`Unreachable` variant (`Revoked`/`RateLimited`/`Rejected`, depending on the
iteration). The fixture's server loop has then spent its only accept, so the bearer test's own
request is accepted by the kernel backlog but never answered and waits on the 30 s production
deadline, and the 3 s join expires. One collision explains both failures in one run. This
matches the measured reuse rate and the source trace. It does not depend on CPU pressure, the
blocking gateway or reqwest resolver work, so paused time or a wider bound would hide the race
instead of removing it.

### O1 — the refused-connection test reserves its port for the whole dial

The redacts test obtains its unreachable address from a socket that stays bound to
`127.0.0.1:<port>`, never listens, does not set `SO_REUSEADDR`, and lives until
`revoke_token` has returned. The test still exercises the production service against a
real refused (or, on Windows, refused-after-retry/timeout) connection and still asserts
`LichessRevocationOutcome::Unreachable` and `assert_token_free_outcome`. The 2 s client timeout
stays. Implementation choice (`tokio::net::TcpSocket` bound without `listen`, which tokio does not
mark `SO_REUSEADDR` unless asked, or an equivalent already-available API) belongs to the executor,
under the constraint that no new dependency is added.

### O2 — the reservation is proven, so reverting O1 goes red

While the reservation is held, the test asserts that `std::net::TcpListener::bind` on the same
address fails with `std::io::ErrorKind::AddrInUse` (measured above: Linux `EADDRINUSE` even
though `std` sets `SO_REUSEADDR`). With the pre-fix `drop(listener)` the same assertion fails
deterministically, so the regression guard is not probabilistic. The test does not loop or sleep
to provoke the original collision.

### O3 — no change to the shared loopback fixture or to production

`loopback_revocation`, its 3 s join and the bearer test are unchanged: their failure was a
consequence of a foreign connection, and after O1 nothing else in the crate dials a port it does
not own (Traced premises). Production `oauth.rs` code, `REVOCATION_TIMEOUT` and the outcome
mapping are unchanged.

## Decisions and trade-offs

* **Question:** how does f-20261101-02 remove the paired revocation-test failure?

## Approach

### Answer to the open question

Root cause: ephemeral-port reuse. The redacts test frees port P and dials it after a delay; under
a parallel suite a `loopback_revocation` fixture can be handed P. Its single scripted response
(for the bearer test, e.g. `200 OK`) answers the redacts test's DELETE, so the redacts test
observes a non-`Unreachable` variant (`Revoked`/`RateLimited`/`Rejected`, depending on the
iteration). The fixture's server loop has then spent its only accept, so the bearer test's own
request is accepted by the kernel backlog but never answered and waits on the 30 s production
deadline, and the 3 s join expires. One collision explains both failures in one run. This
matches the measured reuse rate and the source trace. It does not depend on CPU pressure, the
blocking gateway or reqwest resolver work, so paused time or a wider bound would hide the race
instead of removing it.

### O1 — the refused-connection test reserves its port for the whole dial

The redacts test obtains its unreachable address from a socket that stays bound to
`127.0.0.1:<port>`, never listens, does not set `SO_REUSEADDR`, and lives until
`revoke_token` has returned. The test still exercises the production service against a
real refused (or, on Windows, refused-after-retry/timeout) connection and still asserts
`LichessRevocationOutcome::Unreachable` and `assert_token_free_outcome`. The 2 s client timeout
stays. Implementation choice (`tokio::net::TcpSocket` bound without `listen`, which tokio does not
mark `SO_REUSEADDR` unless asked, or an equivalent already-available API) belongs to the executor,
under the constraint that no new dependency is added.

### O2 — the reservation is proven, so reverting O1 goes red

While the reservation is held, the test asserts both properties O1 relies on, before the
production call:

* **Held:** `std::net::TcpListener::bind` on the same address fails with
  `std::io::ErrorKind::AddrInUse` (measured above: Linux `EADDRINUSE` even though `std` sets
  `SO_REUSEADDR`). With the pre-fix `drop(listener)` this fails deterministically.
* **Refusing:** a direct `std::net::TcpStream::connect_timeout` to the reserved address fails with
  `std::io::ErrorKind::ConnectionRefused`. Its timeout is a generous hang detector (several
  seconds, enough for Windows' SYN retries against a non-listening port), not a latency bound.

  stays green, and the revocation would only reach `Unreachable` through the 2 s client timeout.

The regression guard is therefore not probabilistic. The test does not loop or sleep to provoke
the original collision.

  socket for the whole dial, and assert the reservation. **Rejected:** (1) paused tokio time or a
  wider 3 s join bound — the measured cause is a foreign connection, not latency, so both hide the
  race (and a longer join only delays the same red); (2) dialling a fixed "never-listening" port

  requests — treats the symptom in the victim, and the redacts test would still observe a foreign
  server's answer. **Reason:** measured reuse 5/20000 and zero reuse while held; one-test change;
